# Migrating from GopherLua

## Drop-in use

The module path is unchanged. Add a `replace` directive and rebuild:

```bash
go mod edit -replace github.com/yuin/gopher-lua=github.com/croessner/gopher-lua-jit@v0.2.1
go mod tidy
```

With `lua.NewState()` or an `Options` value that sets neither
`LanguageVersion` nor `JIT`, the runtime behaves like GopherLua v1.1.2 with
the bug fixes listed below. Libraries written against the GopherLua API
(for example gopher-lua-libs, gluamapper, gopher-luar) compile unchanged.

### Behaviour changes in the default (Lua 5.1) profile

These are fixes of upstream defects; code that depended on the old
behaviour was already incorrect Lua:

| Area | Upstream GopherLua | This runtime |
|---|---|---|
| `a, b = b, a` on locals | each value was stored as soon as it was computed (`a, b = b, a` gave `2 2`) | all right-hand sides are evaluated first |
| `a = 2, f()` on a local | `a` was assigned before `f` ran | surplus expressions run before the assignment |
| `v = t.x and y` / `v = f() and y` on an existing local | `v` kept its old value when the left operand was false or nil | `v` receives the left operand |
| `w = (f() or 2) and w + 1` on an existing local | the target was overwritten before later operands read it | operands see the old value |
| `s = (s:gsub(...))` where `s` is the last parameter | corrupted the locals declared after the parameters (Go nil values, crashes) | works |
| `goto` | every `goto` closed all upvalues of the function, so closures stopped sharing locals with it | only the scopes left by the jump are closed |
| `{1, a = f()}` | the results of a call in a keyed last field were also stored as array items | only the key is assigned |
| `table.sort` after `t[#t] = nil` | compared the removed (nil) element | sorts the elements up to the border |
| Upvalues after a caught error | an error caught by `pcall` closed the upvalues of **all** active functions, so closures and their enclosing function stopped sharing locals | only the frames unwound by the protected call are closed |
| `for x in f do` with fewer than three values | missing control values kept stale register contents | missing values are `nil` |
| Table constructors with more than 25550 items | items beyond that were dropped | all items are stored |
| `-0.0` in arithmetic results | became `+0.0` | preserved |
| `local f = function() return f end` | the inner `f` was the new local | the inner `f` is the outer/global `f` (only `local function f` is recursive) |
| Yield across `pcall`, a metamethod or an iterator | corrupted the coroutine (later crash) | raises `attempt to yield across a C-call boundary` |
| `--[==x` | "invalid multiline comment" | a line comment, as in Lua |
| Parser | generated by goyacc | hand written; the generated symbols (`yyParse`, `yySymType`, `parse.UNARY`, …) of package `parse` no longer exist |
| Nesting depth of syntax | unlimited (deep nesting overflowed the stack) | at most 200 nested levels of blocks, parentheses and expressions, like reference Lua |
| `\v` and `\f` between tokens | "Invalid token" | whitespace, as in Lua |
| More than 255 upvalues in one function | index out of range panic at run time | compile error |
| Order of `pairs` / `next` / `ForEach` | array part, then hash keys in insertion order (`ForEach`: in random order) | array part, then string keys in insertion order, then other keys in insertion order; `ForEach` uses the same order |
| `L.NewTable()` | reserved a 32 element array and a hash map for every table | allocates both parts on first use |
| Memory and time for integer keys far apart (`t[i * 1000] = v`, ids as keys) | every key below about 67 million grew the array part up to the key: 20000 such keys took over a second and a gigabyte | proportional to the number of elements; what Lua code and the Go API observe (`#t`, `table.maxn`, the order of `pairs`, `table.insert`, `table.remove`) is unchanged |

Deliberately kept from GopherLua although reference Lua 5.1 differs: a call
continued on the next line (`f(1)` newline `(g)(2)`) is one statement,
repeated field separators in table constructors (`{1, , 2}`) are accepted,
and the array part of a table keeps the slot of an element that is set to
`nil`: after `t = {1, 2, 3}; t[3] = nil`, `table.remove(t)` removes that
slot and returns `nil`, and only the next call returns `2`. `table.insert`
with a position counts such slots as well. This holds for every
representation of a table, with and without the JIT; the test
`TestTablesBehaveLikeUpstream` compares random sequences of table
operations with the results of upstream GopherLua v1.1.2
(`testdata/table_compat_upstream.txt`, written by
`benchmarks/tablecompat`).

## Opting into Lua 5.5

```go
L := lua.NewState(lua.Options{LanguageVersion: lua.Lua55})
```

What changes for Go code:

- **Integers are a separate type.** Lua integers are `lua.LInteger` (int64),
  floats stay `lua.LNumber` (float64). Both report `Type() == lua.LTNumber`.
  - `v.(lua.LNumber)` no longer matches integer values. Prefer
    `lua.LVAsNumber(v)`, `L.CheckNumber`, `L.CheckInt`, `L.CheckInt64`,
    `L.ToInt`, or the new `L.CheckInteger`, `L.ToInteger`, `lua.LVAsInteger`.
  - `L.Push(lua.LNumber(3))` pushes the *float* 3.0, which Lua code prints as
    `3.0`. Push `lua.LInteger(3)` for integers. (This mirrors
    `lua_pushnumber` versus `lua_pushinteger` in the C API.)
  - Table keys: integral float keys are normalized to integer keys, and
    `ForEach`/`Next` report integer keys as `lua.LInteger`.
- **Globals** are resolved through the `_ENV` upvalue. `L.SetFEnv` on a Lua
  function replaces its `_ENV`; `setfenv`/`getfenv` do not exist in Lua.
- **Removed Lua 5.1 library functions** (`unpack`, `loadstring`, `math.pow`,
  `table.getn`, `string.gfind`, …) are absent, as in Lua 5.5.
- Precompiling: use `parse.ParseWithOptions(r, name, parse.Options{Version: parse.Lua55})`
  and `lua.CompileWithOptions(chunk, name, lua.CompileOptions{LanguageVersion: lua.Lua55})`.
  `L.Load`, `L.LoadString`, `L.DoString` and `L.DoFile` pick the profile of the state.
- A prototype compiled for one profile should be run by states of the same
  profile.

## Enabling the JIT

```go
L := lua.NewState(lua.Options{JIT: lua.JITOptions{Enabled: true}})
```

Nothing else changes: results are identical to the interpreter (this is
what the differential tests check), with one caveat for debuggers:
`debug.getlocal` on a frame that runs native code can show an outdated
value for a variable that is not used any more. See [jit.md](jit.md) for
options, diagnostics and limits. If the platform is unsupported the option
is ignored.

New API surface (all additive):

| Symbol | Purpose |
|---|---|
| `Options.LanguageVersion`, `lua.Lua51`, `lua.Lua55` | language profile |
| `Options.JIT`, `lua.JITOptions` | JIT configuration |
| `(*LState).JITStats()`, `lua.JITStats` | JIT statistics |
| `(*LState).JITFlush()` | discard compiled code |
| `lua.LInteger`, `lua.LVIsInteger`, `lua.LVAsInteger` | integer subtype |
| `(*LTable).Clone()` | shallow copy of a table without its metatable |
| `(*LState).CheckInteger`, `OptInteger`, `ToInteger`, `CheckNumberValue` | argument helpers |
| `lua.CompileWithOptions`, `lua.CompileOptions` | profile aware compiler |
| `parse.ParseWithOptions`, `parse.Options`, `parse.Version` | profile aware parser |
